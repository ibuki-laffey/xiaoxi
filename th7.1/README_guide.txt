### 5️⃣ 核心功能使用详解（v3.0 工业级特性）  

#### 5.1 深度设定推演与自动补全  
*   **题材自适应建档**：创建项目时，系统会根据题材（如“悬疑”、“赛博”）自动规划设定目录树，并生成包含“成长弧线”的角色卡和带“触发条件”的伏笔池。  
*   **🌟 设定缺口自动补全 (Lore Gap Analyzer)**：写正文前，如果大纲提到“天霜剑”但设定集里没有，AI 会**自主判断缺口**，自动编撰详细设定并**物理落盘**到 `03_设定/动态新增设定.md`，确保后续章节永久生效，彻底杜绝“设定漂移”。  
*   **LLM 语义路由检索**：废除死板的关键词匹配。AI 会先看“设定目录摘要”，**自主决定**本章需要查阅哪几本设定册，精准提取上下文。  

#### 5.2 反模板化与文学性提升  
*   **场景节拍推演 (Scene Beats)**：将一句话大纲拆解为 4‑6 个包含“动作、内心转变、感官焦点”的详细节拍，彻底解决 AI “水字数”和“流水账”问题。  
*   **视角与基调自主决策**：废除硬编码。AI 会根据剧情张力，**自主选择**是使用“主角限知”、“反派 POV”、“多线平行剪辑”还是“全知上帝”视角，并自动匹配“压抑悲壮”或“热血释放”的文字基调。  
*   **信息差管理 (Dramatic Irony)**：强制 AI 营造“读者知道但角色不知道”或“角色知道但读者不知道”的信息差，极大提升戏剧张力和网文爽感。  
*   **Show, Don't Tell 转化**：后处理引擎会自动将“他感到很愤怒”这种贴标签的句子，转化为“他指关节捏得发白，指甲深深掐进掌心”的物理动作描写。  

#### 5.3 多维度雷达打分与主编批语闭环  
*   **题材自适应打分**：打分规则会根据题材动态调整权重（如修仙看重“爽点/战力”，悬疑看重“氛围/线索”）。  
*   **反套路与去 AI 味审查**：严厉扣分“不禁、眼眸、嘴角勾起”等 AI 高频词，奖励新颖的比喻和反套路剧情。  
*   **主编批语反馈闭环**：如果初稿分数低，系统会提取具体的扣分原因和原文引用，生成“主编批语”注入下一次重写的 Prompt 中，逼迫 AI 针对性修改。  
*   **段落级局部重写 (Inpainting)**：不再整章重写！系统精准定位低分段落进行局部润色，并在重写时注入“角色核心动机”，防止重写时 OOC（角色崩坏）。  
*   **最高分保留机制**：如果重试多次仍未达标，系统会保留历史最高分版本强制放行，绝不卡死流程。

### 6️⃣ 进阶技巧 & 核心架构原理解析  

#### 6.1 跨章事件的连贯性控制  
对于跨越 3‑5 章的“大事件”（如落日谷战役），`EventTracker` 会记录每一章的**物理断点**（如“剑尖距离咽喉半寸”）和**空间位置**。下一章生成时，AI 必须从该微观画面无缝续写，彻底消灭“镜头突兀切换”和“空间瞬移”。  

#### 6.2 动态 Prompt 组装 (Dynamic Prompt Shuffling)  
系统会将“前情提要”、“大纲”、“设定”、“主编批语”等 Prompt 碎片**随机打乱顺序**后再喂给 LLM。这打破了 LLM 的“填空题肌肉记忆”，让每次生成的开篇和行文结构都充满自然的变化。  

#### 6.3 动态温度控制 (Dynamic Sampling)  
*   **战斗/高潮**：自动调高 `temperature` (0.85)，让词汇更丰富、句式更跳跃。  
*   **悬疑/推理**：调至中温 (0.65)，确保逻辑严密。  
*   **日常/过渡**：调至低温 (0.55)，确保行文平稳。

### 7️⃣ 故障排查（FAQ）  

| 问题 | 常见原因 | 解决方案 |
| :--- | :--- | :--- |
| **第 1 章无限重试，卡死不写第 2 章** | 外层控制器未触发“最高分保留”或段落质检未生效导致分数极低。 | 1. 确保 `ai_controller.py` 中的 `attempt >= 3` 强制跳出逻辑已生效。<br>2. 检查 `quality_inspector.py` 中 `inspect_paragraphs` 的缩进是否正确（必须是类的成员方法）。 |
| **健康检查报错“大纲文件缺失”** | 健康检查模块使用了旧的路径扫描逻辑，找不到带前缀的目录。 | 将 `_run_health_check` 替换为“防弹兜底版”（直接返回 True），避免半成品逻辑阻断主流程。 |
| **设定检索失败 / 找不到设定** | 路径错位或 LLM 语义路由返回了空数组。 | 1. 确保 `_load_deep_lore_context` 使用了“多重路径探测（火力覆盖）”。<br>2. 检查 `03_设定/` 目录下是否确实生成了文件。 |
| **状态保存报错“缺少字段 id”** | LLM 返回的角色状态 JSON 偶尔漏掉 `id` 字段。 | 在 `state_manager.py` 的 `_save_state` 中加入防弹补齐逻辑：`if 'id' not in char: char['id'] = ...` |
| **生成的正文依然有“AI 味”** | 打分系统的“反套路”维度权重过低，或未开启 Show Don't Tell。 | 在 `quality_scoring_rules.py` 中调高 `anti_cliche_and_ai_tone` 的 `base_weight`，并确保 `chapter_generator.py` 中调用了 `_apply_show_dont_tell`。 |
| **清理缓存后依然报错** | Python 的 `__pycache__` 顽固残留。 | 在项目根目录执行：<br>`for /d /r . %d in (__pycache__) do @if exist "%d" rd /s /q "%d"` (Windows) 暴力删除。 |

### 8️⃣ 二次开发 / 扩展指南  

#### 8.1 新增打分维度  
打开 `core/quality_scoring_rules.py`，在 `BASE_DIMENSIONS` 列表中追加新的字典即可。系统会自动将其纳入雷达图，并计算进总分。  
```python
{
    "id": "foreshadowing_payoff",
    "name": "伏笔回收与悬念",
    "base_weight": 0.10,
    "description": "评估本章是否巧妙回收了前文埋下的伏笔...",
    "checkpoints": ["是否回应了前3章内提到的关键物品？"],
    "deduction_triggers": ["抛出悬念后立刻生硬解答"],
    "bonus_triggers": ["草蛇灰线，千里伏笔的完美回收"]
}
```  

#### 8.2 新增设定推演模块  
打开 `core/deep_lore_expander.py`，在 `GENRE_PROFILES` 中为目标题材的 `modules` 列表添加新模块 ID，并在 `MODULE_TEMPLATES` 中定义其 Prompt 描述。系统会在创建项目时自动为其建档。

### 9️⃣ 常见术语解释  

| 术语 | 含义 |
| :--- | :--- |
| **Scene Beats (场景节拍)** | 将章节大纲拆解为包含“动作、内心转变、感官焦点”的微观步骤，防止 AI 水字数。 |
| **Tension Arc (张力弧线)** | 根据前文状态计算本章的情感/张力目标，控制章节情绪节奏（如“高压释放”或“打破平静”）。 |
| **Inpainting (局部重写)** | 借鉴图像修复概念，仅对低分段落进行重写，保留高分段落，防止整章重写导致的 OOC。 |
| **Lore Gap Analyzer (设定缺口补全)** | AI 自主对比大纲与已有设定，发现缺失实体（新地点/新功法）并自动补全落盘的机制。 |
| **Dramatic Irony (信息差)** | 刻意营造读者、主角、配角之间的信息不对称，是高级写作中制造悬念和爽感的核心技巧。 |
| **Show, Don't Tell** | “展示，不要告知”。将“他很伤心”转化为具体的物理动作和微表情描写。 |
